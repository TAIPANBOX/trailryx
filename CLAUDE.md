# Working on Trailryx

**Before writing a line of code, read [`docs/planning/trailryx-architecture.md`](docs/planning/trailryx-architecture.md) and [`docs/planning/trailryx-plan.md`](docs/planning/trailryx-plan.md) in full.** They are the approved decisions; this file is only their enforceable summary, and where the two disagree, those two win. [`docs/planning/trailryx-roadmap.md`](docs/planning/trailryx-roadmap.md) is the single source of what order things happen in.

Everything below is a rule, not a description. Each one says what holds it today:

- `(gate: <path>)` a check that refuses the push, written once in `scripts/` and called by both `.githooks/pre-push` and CI.
- `(test: <name>)` a test, and nothing else.
- `(not checked)` this line is the only thing holding it. Treat those as the fragile ones.

---

## Invariants

1. **Never write `unsafe`.** The workspace lint forbids it and the gate greps for it anyway, because a lint can be relaxed in a manifest by somebody who meant well. *(gate: scripts/no-unsafe.sh)*

2. **Never add a third-party dependency to the core or to `trailryx-verify`.** A dependency belongs in an L2 adapter, and that adapter's crate name must be added to the allow-list in the gate script before its dependency will build. The reason is not minimalism: an auditor reads the verifier, and every crate pulled into it is a crate they are asked to trust instead of read. Everything else (a validated cipher, a post-quantum KEM, TLS, a SQL engine) is taken from whoever does it better than we would, because nobody buys a proof store for its author's AES. *(gate: scripts/declared-deps.sh)*

3. **The core must build and pass its tests with every adapter absent.** If it cannot, an adapter has got into the foundation. *(gate: scripts/declared-deps.sh)*

4. **Never read a clock, a random number, a disk or a socket directly from the core.** Go through `Clock`, `Rng`, `Io`, `Net`, or deterministic simulation stops working and every guarantee built on it stops meaning anything; breaking this does not announce itself, it shows up as two runs of one seed that no longer agree. *(gate: scripts/determinism.sh)*

5. **Never put free text in the metadata plane.** Typed fields only: identifiers, enums, hashes, numbers, timestamps. Any prose lives in the encrypted payload plane under the subject's key, or `forget` leaves personal data behind and the promise is false. *(test: no_prompt_text_reaches_the_metadata_plane)*

6. **A mapper that does not know where an attribute belongs puts it in the encrypted plane.** Never in metadata, never dropped. *(test: every_attribute_lands_in_exactly_one_plane)*

7. **Never redefine a field in place.** The record and journal formats are frozen: a change is a new version plus a migration, and old versions keep parsing. *(test: a_version_two_pack_still_parses)*

8. **Do not add a post-quantum signature in v1.** The KEM is hybrid X25519 + ML-KEM-768 from day one because crypto-erasure only lasts as long as the KEM; the segment signature stays ES384, and SLH-DSA waits for a validated implementation. *(test: defaults_are_the_post_quantum_ones)*

9. **Never remove an algorithm from the verifier.** Mark it weak. Dropping ES256 destroys the provability of everything signed with it. *(not checked)*

10. **Never compile a compliance framework's vocabulary into the format or the core.** The mapping is its own versioned crate, because the standards it maps to are still drafts. *(not checked)*

11. **Never claim compliance in anything this repository emits.** The wording is "covers the requirements of Article 12", not "compliant", until a standard is cited in the Official Journal. *(test: nothing_this_crate_emits_says_compliant)*

12. **Records arrive only through a `Source`.** SQL reads; it never writes, or the journal stops being the only truth. *(test: every_way_of_writing_is_refused)*

13. **An answer whose predicates do not all land on the provable dimensions must say so.** Mark it partial rather than let a reader take it as proved. *(test: a_predicate_off_the_provable_dimensions_answers_correctly_and_says_partial)*

14. **Every adapter passes the conformance suite before it enters a build.** *(test: reference_object_store_conforms, and its siblings in `crates/trailryx-contracts/tests/conformance_suite.rs`)*

15. **Never fix the shard count by counting cores, and never re-split it.** Shard identity is inside proof paths, so redistributing afterwards breaks proofs already issued; a different count is a new store epoch with explicit lineage. *(not checked)*

16. **If two places need the same value, export it from one and import it in both.** Two functions computing what is meant to be one number is how a publisher and a reader end up disagreeing about the same object. The same holds for a number written in prose, and there it is worse, because nothing compiles it: the facade's dependency count sat in five places, the README's copy was corrected within hours of being wrong and a doc comment's copy was fifty crates out for six days, in the file whose subject it was. One value in prose now means one owner in prose. For that count the owner is the README, whose figure the gate measures against `cargo tree`, and no other tracked file may state a count of its own. The same now holds for the number of checks the gate itself runs, which drifted three times in one day and cost five hand edits each time: the hook and CI are counted and must agree, the README states the figure, and everything else says "the same checks". `CONTRIBUTING.md` had said twelve since the day it was written, against eighteen at the time, with a list that left out six of them, and nothing had ever looked. A superseded figure may appear where a sentence is recording history, and it has to be declared with a reason that is re-derived on every run, exactly as invariant 24 requires of a silenced advisory: `history` means the paragraph carrying the number also says when, and a paragraph that stops saying when stops being exempt. The third copy this bites is a **vocabulary**, and it is the worst of the three because the copy that rots is the one that leaves the building: each closed enumeration is written once as a Rust enum the compiler checks and once in the schema document `Schema::to_json()` publishes, and `algorithms.signature` listed `es256`, `ml-dsa-65` and `slh-dsa` for as long as the store had been signing with `SigAlg::Es384`, so the format's own published description denied the existence of the value every record it wrote was carrying. A reader who trusted it would have planned the 2030 re-signing against the wrong set, which is the one job those fields have. *(gate: scripts/readme-numbers.sh, for the dependency count; test: `the_schema_document_lists_exactly_the_variants_that_exist` for the schema's vocabularies, with `every_closed_vocabulary_in_the_schema_is_held_against_an_enum` beside it because a table of pairs is itself a second copy and an unlisted field would go unchecked while the suite reported a pass; the general rule about two functions computing one number is still not checked)*

17. **A check with any logic or parameters of its own goes in `scripts/`, and both the hook and CI call it.** Bare `cargo` invocations may stay written out in both; anything carrying a seed, a flag, a pattern or a list may not, because that is what drifts. *(not checked, and it is a rule because a drifted copy once made CI refuse a push the hook had passed)*

18. **Never let a test wait without a bound.** A hanging test reports nothing at all: no failure, no name, no output, which is less than a wrong answer tells you. It is also the failure a fake grows INTO rather than starts with: teaching the S3 fake to refuse a malformed request turned one failing test into a run that never ended, and finding that cost more than the bug it was hiding. The Azure fake was copied from the same template before that lesson and never got it, so on 6 August 2026 it still had neither of the two bounds, and the two are one failure: a client that connects and says nothing leaves the fake blocked in `serve`, so its thread never returns, so the channel never closes, so the test's own `recv()` waits for a message from a thread that was never going to send one. *(gate: scripts/bounded-waits.sh, which refuses a bare `.recv()` in test code and an `accept()` whose file never sets a read timeout, both chosen because the bounded form is the same call in the same API and so can be demanded mechanically. It found the Azure fake on its first run, before anything was changed, which is the only reason to believe it. Its limits are declared in the file and repeated in the debt list, and one of them was forced rather than chosen: keying the socket rule on `TcpStream::connect` as well flagged a test that connects to a dead port expecting refusal and never reads, so taking a socket is not the same as waiting on one.)*

19. **Never report "nothing found" without a run where the same check does find something.** A check that cannot fail reports zero forever. *(test: the_harness_catches_a_lying_fsync)*

20. **A fake must refuse what a compliant server refuses.** A fake written from the same reading of the same documentation as the client agrees with the client's mistakes, so it has to be taught the rules the client is not allowed to break. *(test: the_request_carries_exactly_one_host_header)*

21. **A peer's name comes from its certificate, never from anything it sent.** The completeness rule counts answers against a signed registry, and that count is worth nothing if a name can be claimed: one node holding one valid federation certificate could otherwise answer to every missing name in turn and stamp the result complete. The client names the peer it expects, TLS refuses a certificate that does not carry it, and no field in the response body takes part in the decision. *(test: a_peer_cannot_answer_under_a_name_its_certificate_does_not_carry)*

22. **A federated stream that ended without its trailer is not an answer.** The proof status rides last precisely so that its absence is a signal. Rows that arrived without a claim attached are refused rather than returned, because a truncated answer that reads as a small complete one is the exact failure the federation rule exists to prevent, one layer down. *(test: a_stream_that_ends_before_its_trailer_is_refused_rather_than_read_as_complete)*

23. **An identifier arriving from a peer is parsed at the strictness of the ingest door, not of the journal.** `trailryx-journal` reads ids back with the lax constructor because it wrote them; `trailryx-otlp` uses the strict one because those came from outside. A peer is outside wearing the journal's clothes, and the transport got this wrong the first time it was written. *(test: an_agent_id_that_is_not_a_uri_is_refused_the_way_the_ingest_door_refuses_it)*

24. **A silenced advisory carries a reason, and the reason is re-derived on every run.** `cargo audit` reads the lockfile, which is correct, and therefore flags crates cargo records but never compiles. Silencing one of those is sometimes right; silencing it with a sentence in a configuration file is not, because the sentence stops being true without saying so and the entry then protects nothing while still reading as a decision. Two reasons are allowed and both are facts rather than judgements: `never-built`, the crate is in no build graph because it sits behind an optional feature nothing enables, and `dev-only`, the crate is compiled for tests but reaches no normal dependency edge. The second is the weaker one and says so: it means the code is not in a shipped artifact, not that it never runs here. An id silenced with no recorded reason fails the gate outright. *(gate: scripts/audit.sh, verified by pointing each reason at a crate that breaks it and by adding an unexplained id, all three of which fail it)*

25. **A peer's chain is recomputed before its records are adopted, and a run that does not continue a head this receiver holds is refused.** Registry membership is authorisation, not evidence: it says a peer may speak, not that what it said links up. Replication is where the difference bites, because accepting records means adopting a history. The receiver hashes bytes IT produced by re-encoding what it decoded, never a link that travelled with the record, which is the same rule `store::tier` already follows when it warms a segment. Two entry points and not one with a flag: `accept_from` takes the head this receiver holds, and `accept_unanchored` is named so that choosing the weaker check is visible in the calling code, because a fabricated history is internally consistent and passes it. *(test: the eleven in `crates/trailryx-federation/tests/replication.rs`, each reaching one refusal, all verified by breaking the implementation five ways; plus `crates/trailryx-federation-grpc/tests/replication_over_the_wire.rs`, which holds the assumption the whole thing rests on: a record's canonical bytes survive protobuf unchanged, so a lossy codec would report a broken chain rather than itself)*

26. **A reader is never told about somebody else's answer.** `trailryx_proof()` says how provable the last answer on **this session** was, and over the Postgres facade a session is a connection: `serve_on` forks one per accepted socket, so the proof slot, the table and the `SessionContext` are that connection's own. Anything shared between connections must be immutable, which the sealed segments are. This was live: one slot served the whole process, so a client that ran a query the index could not prove and asked for its proof could be handed a stranger's `full`, and a connection that had asked nothing was told about a query it never ran. An unproved answer taken as proved is the failure the entire crate is arranged against, and it arrived through the function meant to prevent it. What remains, and is stated rather than fixed, is one session's own race: a second statement between a query and the proof that asks about it overwrites the slot. *(test: `two_connections_each_read_their_own_proof_and_never_the_others` and `a_fresh_connection_has_proved_nothing_however_busy_the_server_is` in `crates/trailryx-sql/tests/wire.rs`, both verified by failing against the shared slot; a gate would have to prove a negative about code not yet written, which is the same reason 21 to 23 are tests)*

27. **The SQL read surface admits or refuses a connection, and never filters a row.** One `Action::Query` decision at connect time, against a scope fixed when the server was built. Past it every authenticated client reads every record in every segment that server registered, whatever the `tenant` field says, and nothing on the read path takes a principal or a tenant. The deployment model is **one server per scope**; two tenants means two servers. This is a constraint and not a defect, and the rule is that it stays written where a deployer meets it: `SECURITY.md`, the README's SQL section and `ReadGate`'s own documentation. Adding row filtering later does not delete this line, it replaces it, because the line a deployment was built on must not quietly stop being true. *(not enforced, and the thing most likely to break it is not code: the unit tests showing two scopes refusing each other's principals read as tenant isolation, so anybody reading them without this line concludes the opposite)*

28. **A declared limit is read by the code it bounds, and what it does is held by a test. A limit that is neither is deleted, not documented.** `Config::max_connections` on the SQL surface was declared with its reason beside it, "a read surface with none is a read surface that can be exhausted", and nothing read it: `serve_on` spawned a task per accepted socket and counted none of them, so lowering the number changed nothing at all. An absent bound is a gap somebody can see. A declared bound with a paragraph of justification reads as a mitigation already applied, and it is the paragraph that gets believed, which is why this is worse than the field not existing. At the cap the connection is **answered rather than dropped**, the same choice `trailryx-ingest` makes at its own: a socket that closes without a word is what a client also sees on a crash, a firewall and a wrong password, so it carries no information, while `53300` is the one condition on this port worth retrying. *(gate: scripts/config-fields.sh, which finds a field nothing reads and, run against the commit before this one, names exactly that field; the gate cannot prove a field is obeyed, so the two tests in `crates/trailryx-sql/tests/wire.rs` hold that half, verified by breaking the implementation four ways: a guard that never returns a slot, `>=` for `>`, a close with no answer, and a message length that forgets to count itself)*

29. **A test's scratch directory carries the process id, always, and not only when a collision has been seen.** `$TMPDIR` belongs to the user, not to the run: a fixture named after itself is a fixture the next process names identically, and both the pre-clean and the `Drop` that tidy it up name it by path rather than by ownership. Whoever wipes first takes the other's files, and the report is a file that was written and then was not there, which points at everything except the run that removed it. Measured on 6 August 2026, eight copies of one test binary at once: the anchor's authority failed 11 of 30 processes before and 0 of 60 after, the ASN.1 oracle 12 of 40 before and 0 of 40 after. The rule is mechanical rather than judged, because the nine sites that had never been seen to fail were written by people who would each have judged their own fixture safe, and one of them was. *(gate: scripts/temp-paths.sh, verified by putting a constant path back and by adding a new fixture with one, wrapped across two lines so the statement rather than the line is what is read)*

30. **The hook that runs is the one the pushed commit carries.** `core.hooksPath` is set once and *relatively*, to `.githooks`, and a relative value resolves inside whichever worktree git is running in, which is what makes one setting correct for all of them. A worktree may override that in its own `config.worktree` with an absolute path into another checkout, `extensions.worktreeConfig` is on here, and this is not hypothetical: every worktree under `.claude/worktrees/` was created carrying exactly that override. What it does is split the gate across two commits, because the hook's first act is to `cd` to the pushed worktree: the LIST of checks comes from whatever branch the other checkout happens to have out, and the checks themselves come from the commit being pushed. One direction is loud and merely expensive, a hook calling a script the pushed branch does not have, which refused a push on 6 August 2026. **The other direction is silent, and is the reason this is a rule:** an older hook runs fewer checks than the commit requires and prints that all of them passed, which is invariant 19 wearing the gate's own clothes. *(gate: scripts/hooks-path.sh, called by the hook before any check runs, verified in both directions against a real worktree by restoring the override and removing it again, and in its other branch by hiding the script from a hook that calls it. It is deliberately not one of the counted checks and CI does not call it, because CI has no hooks to ask about.)*

31. **A scratch path is removed by the file that made it, and this is the debt invariant 29 took on rather than a separate idea.** Putting the process id into a fixture path was right, and it changed the price of never deleting one. A constant path nothing wipes is a single stale directory, reused by every run for as long as the machine lives, which is why five of them sat here unnoticed. The same path with a process id in it is a **new** directory on every run, so the fix turned a leak that did not grow into one that does. Measured on 6 August 2026, five runs of each affected suite: `signed` left 55 directories holding 55 EC private keys, the OTLP JSON oracle 5 holding 80 files, `two_verifiers` and `inflate` 5 each. **The keys are the part worth the rule.** They are throwaway test keys and nothing there is secret; a fixture that leaves key material lying about teaches that leaving key material lying about is normal, and that habit is not confined to fixtures. Where the removal goes is a judgement the gate cannot make and the author must: `inflate` needed its wipe ABOVE two early returns, and the OTLP oracle needed its wipe BELOW the assertion, because that assertion names the file it failed against and a message pointing at a deleted path is worse than no path at all. A `Drop` guard is the wrong tool there for exactly that reason, and the right one on `Openssl`, which owns its directory and has nothing to leave behind. *(gate: scripts/scratch-cleanup.sh, which counts each `temp_dir()` binding against the `remove_dir_all` calls naming it and, run against the tree as it stood before the two fixes, reports all five; counting rather than merely looking is what reaches the projection oracle, which had two fixtures and one wipe and would pass any check asking whether the file removes anything. Its two blind spots are measured, not assumed: a pre-clean satisfies the count exactly as a real wipe does, verified by deleting `anchored.rs`'s `Drop` and watching it still pass, and a wipe below an early return is one it cannot see past. Both are the removal being in the wrong place; what it holds is the removal never being written, which is what happened all five times.)*

32. **A gate skips only on positive evidence that there is nothing to check, and it says so when it skips.** Absence of information is not absence of work, and in a hook the two sit one keystroke apart. `git push --delete` ran the entire gate until 6 August 2026, so four merged branches were removed with `--no-verify` instead, and that is the habit worth naming rather than the wasted minutes: `--no-verify` is the same keystroke whether a push carries nothing or carries everything, and a gate people have learned to reach past has stopped being one. The shortcut is therefore written so that skipping needs a positive answer twice over, **at least one ref AND every ref a deletion**, which leaves an empty stdin, a stalled stdin and a mixed push all running everything. The empty case is the one that matters, because it is how `CONTRIBUTING.md` tells people to run the hook by hand, and reading no refs as nothing to do would turn every hand run into a silent pass. **The skip is also decided after, never before, the check that this is the right hook**, because the decision is taken by the file whose provenance is in question, and an unverified hook's idea of what counts as a deletion has not been verified either. *(gate: scripts/deletion-skip-cases.sh, eleven cases, verified by breaking the rule seven ways and watching each one fail: an empty stdin that skips, a mixed push that skips, a stall that skips, a ref count that is not the ref count, a hook that stops calling the decision, a hook that skips without saying so, and the shortcut moved back above the precondition. The decision had to move to `scripts/deletion-only-push.sh` before any of that was reachable, because a check the gate runs cannot test the hook by running it: the cases whose correct answer is "run everything" would run the gate, which would run the check. Two of the eleven are read out of the hook's text rather than executed, the call and the ordering, and one is a real run of the hook on the deletion case, which exits before any check starts and is fenced twice so that a regression cannot launch the gate inside the gate. **The seventh breakage is the one worth knowing about**: the first version of this check stalled with nothing read at all, which the ref count already refuses, so removing the clock went undetected. The case where the clock is the only thing saying no is a deletion AND THEN a stall, and that is what it does now.)*

33. **A segment is sealed if and only if its manifest is beside it, and a reader rebuilds a segment rather than trusting either half.** The write is the local spelling of the conditional write `trailryx-publish` uses in an object store, and it is the commit point for the same reason: a crash between the journal and the manifest leaves a journal the next process keeps appending to, while the other order would leave a published commitment to bytes nobody can read. What follows from it is the part worth stating, because it is what makes a restart safe rather than merely survivable: the highest manifest names the segment that is finished and the head the next one continues from, so `ChainStart::After` comes off the disk and a shard stays one chain across as many files and as many processes as it takes. A reader is then given nothing but the directory: it walks each journal with the same walk recovery uses, re-seals the records, and compares the manifest that falls out with the manifest that was published, so a byte altered anywhere in a segment is refused rather than answered. **The reader writes nothing, not even to repair.** `Journal::open` recovers, which puts a header on an empty file and truncates a tail it will not trust, and a reader that did that would be repairing the evidence it was auditing; `Journal::walk_bytes` is the same walk with no write path attached. *(test: `a_journal_altered_after_sealing_is_refused_rather_than_answered`, `a_second_segment_continues_the_first_across_a_restart` and `records_acked_but_not_sealed_survive_a_restart` in `crates/trailryx-node/tests/plane.rs`, plus `a_reader_walks_the_bytes_without_repairing_them` in `crates/trailryx-journal/tests/journal.rs`, verified by making the walk ignore the chain start it was given, which reports a file that reads as complete instead of a chain broken at sequence one)*

34. **A plane that will not keep something writes that down as a record, in the run it belongs to.** `trailryx-node` has no key custodian and therefore seals no payloads, which is a deployment decision an operator may reasonably make and a silence nobody may. The record's payload reference is simply absent, and an absent reference is indistinguishable from a record that never had one, so the count of declined parts becomes a `StoreEvent` in the affected run. `run_id` is one of the five provable dimensions, which is what makes the note reachable without a new field, a new index or a format version, and it is the same mechanism `Assembler::lost_edge_events` uses for a causal edge that resolved to nothing. The note is written when the segment closes rather than per batch, so it lands beside the records it is about and costs one record per run per segment rather than one per run per drain. *(test: `a_payload_this_process_cannot_seal_is_written_down_rather_than_dropped`; the same rule is `docs/durability.md` §5 for a lost record, and this is the second thing that can be lost)*

35. **A trust domain is the operator's at every door, and a door that takes the identifier whole has to say so out loud.** `trailryx-otlp` enforces it by construction: the mapper builds `agent://<configured domain>/<name>` and a span has nowhere to put a domain of its own. The estate's shared event envelope carries the identifier already assembled, so the same rule has to be a comparison, and without it one valid producer could write records about every agent in the estate under one receiver's tenant. This is invariant 23 read one step further: strict parsing says the identifier is well formed, and only the comparison says it is ours. *(test: `an_agent_from_another_trust_domain_is_refused_rather_than_recorded` and `an_agent_id_that_is_not_a_uri_is_refused_the_way_the_ingest_door_refuses_it` in `crates/trailryx-agentevent/tests/envelope.rs`, both verified by breaking the implementation: the lax constructor at the door, and the comparison removed)*

36. **A value in a closed vocabulary is appended, never renumbered, and the same number is appended everywhere that byte is written.** Adding an event type is not a format version, and working out why is the point of this line: invariant 7 forbids **redefining a field in place**, and a new discriminant defines nothing that was defined before. The field keeps its position, its width and every meaning it ever had; the only new fact is that a byte nobody had assigned now means something. That is why `SigAlg::Es384` is code 4 rather than sitting beside `Es256`, with `FORMAT_VERSION` untouched, and it is why `EventType::NotificationDispatched` is 11.

    What makes it a rule rather than a habit is the second half. The same byte is written in four places that must agree and that no compiler compares: `trailryx_journal::wire`'s `disc!`, `trailryx_index::completeness::event_code`, the proto enum, and the schema document an auditor reads. `trailryx-verify` is the reason the first two matter most, and it never appears in a search for `EventType`, because it reads the byte as a byte and builds its index key from it directly. So a code that differed between the journal and the index would not be a compile error, a lint, or a wrong answer in the store: it would be the offline verifier rebuilding a different index from the same records and condemning a pack that was correct, which is the one failure the product claim cannot survive. Measured by making them differ by one: `segment 1 declares 173aebc1cb41d340 for event_type and its records give 8eafd4f4ef87fc08`, `Broken`.

    The direction that is left is forward, and it is refusal rather than compatibility. A build older than a code refuses a record carrying it, by field and by number, which is what it already does for any byte nobody defined. That is the acceptable answer and the only one: the alternative to refusing an event type you have never heard of is reading it as one you have. *(test: `every_event_code_ever_written_still_decodes_and_the_next_unused_one_is_refused` in `crates/trailryx-journal/tests/journal.rs`, which pins every code ever assigned against the name it was assigned to; `the_schema_document_lists_exactly_the_event_types_that_exist` in `crates/trailryx-record/src/record.rs`; `every_event_type_this_build_writes_is_one_it_can_read_back` in `crates/trailryx-federation-grpc/src/codec.rs`, verified by pointing one variant at another's wire value, which compiles; and `a_heraldyx_dispatch_journal_becomes_records_and_the_recipients_stay_out_of_metadata` in `crates/trailryx-node/tests/events.rs`, which is the one that reaches the verifier and was verified by the disagreement above. The forward direction was measured against the real binary rather than reasoned about: `trailryx-node` built at e9b2a2c, reading a directory this branch wrote, `BadDiscriminant { field: "event_type", got: 11 }`, exit 2.)*

37. **A command that can be put on a timer remembers where it stopped, and it commits that memory after the evidence rather than before.** `trailryx-node events --file` read the whole file on every run, and a record's identity is minted fresh per run, so a second import of an unchanged file produced a second copy of every record while the journal's own deduplication reported `0 duplicate(s)`. Measured before the fix: three imports of a two-line heraldyx journal, nine records in three segments. A scheduled ship would therefore have duplicated the whole trail on every run, and **a duplicated audit trail is worse than an absent one**, because its counts are wrong and nothing says so.

    Deduplicating on the record's identity was the other candidate and it is the wrong one, in three separate ways that are worth keeping written down because the idea is attractive. The `DedupWindow` lives on `Journal`, and `Journal::open` fills it only from the one journal file it opened, so a command that seals and rolls at the end of every run starts each run with an **empty** window: a derived identity would not have fired at all without also loading every id from every sealed segment, which is unbounded work at startup. Past that, the id is a ULID whose high 48 bits are the millisecond it was recorded at, `Ids::mint` guarantees the sequence strictly increases, and the `RecordId` dimension's index is built on those bytes big-endian, so making the id a function of content destroys the order a range over that dimension rests on. `docs/identifiers.md` already refuses to hash an indexed identifier for exactly that reason. And the committed schema calls the field a "ULID of the record itself", which makes changing how it is computed a redefinition of a field in place, with no marker distinguishing an id computed one way from an id computed the other: invariant 7, landing the opposite way from the appended discriminant in invariant 36, because appending a value defines nothing that was defined before and this would redefine everything.

    So the memory is a cursor beside the data, and what it is keyed on is the whole of the design. A path alone is wrong the moment a file is rotated; an inode is not portable and is reused; a byte offset alone is wrong if the file is truncated or rewritten. A cursor here is a **name** and a **position with its evidence**: the absolute path, the bytes consumed, and the hash of exactly those bytes. Only the evidence decides. The prefix still being the head of the file is what makes resuming legitimate, so a shorter file and a rewritten one are both detected rather than resumed into, and both are read whole and say which they were.

    **Every failure points one way, and the ordering is the same rule.** An absent cursor, a torn one, one failing its digest, one naming another path: all are read as nothing remembered, which re-imports. The position is written after the manifest that seals its records, never before. Both choices are the same choice, and it is the journal watermark's: a cursor behind the evidence stores a line twice and the run reports it, a cursor ahead of it skips a line nobody stored and nothing says anything at all. What that costs is measured rather than waved at, because it is larger than it looks: the position moves once per run, so a run killed before its seal costs a re-import of its whole region and not of the part it had reached. Twenty kills in a row over two thousand lines left forty-two thousand records, twenty-one copies of each line, and nothing missing. *(test: the ten in `crates/trailryx-node/tests/cursor.rs`, all ten verified red against a build that read every file whole, including `a_cursor_ahead_of_the_evidence_would_lose_lines_which_is_why_it_is_written_last`, which writes the forbidden cursor by hand and measures the loss it causes; plus the five in `crates/trailryx-node/src/cursor.rs`, one of which found that a cursor missing exactly its trailing byte read back perfectly, because trimming a terminator and having none to trim are the same operation. The residual window, between the manifest's rename and the cursor's, is too narrow to hit with a kill and is measured the only way it can be, by removing the cursor of a run that had sealed: `a_cursor_lost_after_its_records_were_sealed_re_imports_rather_than_losing_the_lines`.)*

## What is a gate, and what is still only a sentence

**Decisions that became gates.** Zero dependencies outside the declared list, the core standing up without adapters, no `unsafe`, a seed reproducing a run byte for byte, the published seed corpus, two independent verifiers agreeing on one pack, a reproducible verifier binary, the TLS builds, every parser under hostile bytes, every number the README states including the image tag it tells people to pull, the facade's dependency count wherever else in the tree it is written down, a 200-seed durability sweep, the advisories with the reasons the silenced ones are silenced, every field of every configuration struct against the code meant to read it, every temp path a test builds, whether anything removes those paths again, the shortcut that lets a push of nothing but deletions run no check at all, and the number of checks itself, counted on both sides. All of them run by `.githooks/pre-push` and again by CI, and how many there are is stated in the README and nowhere else.

**Decisions with no gate yet.** This list is debt, and it is here so it stays visible:

- Invariants 9, 10, 15, 17 and 27 above are held by nothing but their own sentence. Invariant 16 is held in three places and not in general: the facade's dependency count is gated in every tracked file, the gate's own check count is counted on both sides, and the schema's eight closed vocabularies are held against their enums by a test. The general rule, two functions computing what is meant to be one number, is not checked and cannot be by a grep. The vocabulary test is the one to copy if a fourth copy appears, and what makes it worth copying is the second test beside it: the pairing table it reads is itself a copy, so something has to refuse a vocabulary that is in the schema and not in the table.
- Invariants 21, 22, 23 and 26 are held by tests rather than by a gate. A gate would have to prove a negative about code that has not been written yet ("no future call path reads a name out of the body"), and a grep that pretended to do so would be worse than the honest sentence.
- Invariant 18 is gated for the two waits that have a bounded twin and for nothing else. An `.await` that can hang is not flagged, because a grep cannot tell it from one that cannot, and `crates/trailryx-sql/tests/wire.rs` and `crates/trailryx-federation-grpc/tests/across_two_environments.rs` both wait as clients where the bound would be `tokio::time::timeout` around the call rather than an option on the socket. `join()` has no bounded form in std, so there is nothing to demand. A busy loop is invisible to it. Nor does it catch a first `accept()` added to a file whose existing read timeout is on some other socket, because it counts the two and they balance; that was tried, and it passes. What it holds is the shape that has actually bitten here twice, a fake with no bound at all.
- Invariant 32 is gated for what the decision does and only read for what the hook does with it. `scripts/deletion-skip-cases.sh` executes the decision on every case that matters, but two of its assertions, that the hook calls it at all and that the precondition is answered first, are greps over the hook's text and would be satisfied by a call that is written and never reached. The one execution of the hook itself covers the deletion case, because it is the only one that can be run without the gate running inside the gate. **The case with no backstop is still the hand run**, and it is now executed rather than reasoned about: a push that skips when it should not have still meets CI, while `.githooks/pre-push` typed at a prompt meets nothing at all and arrives with no refs on stdin.
- Invariants 33, 34 and 35 are held by tests, and two of the three could not be gated by a grep even in principle: "a reader does not write" is a property of a call graph, and "this domain is ours" is a comparison whose right-hand side is configuration. What a check could hold is narrower and is worth writing when there is a second plane to hold it against: that no path outside `Journal::open` and `Journal::recover` calls `Io::truncate`.
- Invariant 30 is gated forward and not backward. `scripts/hooks-path.sh` runs only when the hook that ran is one that calls it, so a hook older than the check cannot refuse on its behalf. The repair is a configuration change in the affected worktree and the script prints it; what the gate buys is that the fault stops being invisible from the day it is installed.
- Invariant 36 is the one on this list that a gate could hold outright, and that is worth saying plainly rather than dressing up. A script could parse `EventType::X => N` out of `trailryx_journal::wire` and out of `trailryx_index::completeness::event_code` and refuse a push where the two disagree, which is the half with real consequences, and the codes in the proto could be read the same way. What holds it today is the node test that ends at the offline verifier, and that test does bite: making the two differ by one turns it red with the verifier naming the index root. The reason it is here rather than in `scripts/` is a judgement about this change rather than about the rule, and the owner may take it the other way: a new check moves the gate's own count, which lives in the hook, in CI, in `scripts/gate-count.sh` and in the README, and two other sessions were in this tree the day this was written.
- Invariant 28 is gated by half. `scripts/config-fields.sh` proves a configuration field is read; nothing structural proves it is obeyed, and a limit read into a variable and then ignored would pass it. The two tests named beside the invariant are what hold that half, and a third configuration struct arriving without them would be new debt rather than covered by the old.
- The fuzz step differs between the hook and CI on purpose, 300 cases against 3,000: the hook is fast and CI is thorough. Do not "fix" it into agreement.
- **How long the gate takes has one owner and no gate, and cannot have one.** The figure lives in `VALIDATION.md` under *measured on demand*, with its machine, its date and its cache state; the README points at it. A gate could not check it, because the honest answer differs between a laptop and a runner and between a warm cache and a cold one, and a check that fails on a slower machine teaches people to skip checks. It was two sentences disagreeing with each other and with reality until 6 August 2026, both saying the time went somewhere it does not.
- `qryx scan --policy cnsa` is run on demand, not on push.
- ~~The federation transport (gRPC with mutual TLS, decision A2) is specified and unbuilt.~~ Built 2026-08-04 in `trailryx-federation-grpc`, with invariants 21 to 23. ~~What remains unbuilt from stage 12 is verified replication.~~ Built 2026-08-04 in `trailryx-federation::replication`, invariant 25. **Stage 12 is closed.** What it does NOT do is anchor the first link of a run for a receiver holding no prior head for that shard, which is a limit of the problem rather than of the code and is stated in `VALIDATION.md` and in the module.

Numbers, and what has and has not been measured, live in [`VALIDATION.md`](VALIDATION.md). Nothing in this file should restate a number.

## Standing rule

**An approved architectural decision is not finished until it is two things: a numbered invariant in this file, and a gate in `scripts/` if it can be checked structurally.** Until then it is a document, and documents do not stop code. When you make or implement a decision, the last step is to come back here and add the line, or to add the check and then the line.

The corollary is the reason this file exists at all: a decision recorded only in `docs/planning/` is read once, by whoever wrote it.
