# Trailryx 1.5.0

A minor release on the 1.x surface. The seal's Keyryx signer now signs under one key the operator names, and it keeps a signature only after checking it. A node that signs through Keyryx must name the key's thumbprint, so a deployment that set `TRAILRYX_SIGNER=keyryx` without one refuses to start. The frozen section of `COMPATIBILITY.md` is unchanged, and no record, journal, pack or wire format changes.

## Upgrading

Read this section before deploying.

- **A pin is required for the Keyryx signer.** A node with `TRAILRYX_SIGNER=keyryx` and no `TRAILRYX_KEYRYX_KID` refuses to start. Set `TRAILRYX_KEYRYX_KID` to the `kid` Keyryx publishes for the key the seal should sign under: the RFC 7638 thumbprint of that P-384 key, 43 base64url characters. A malformed value also refuses to start. A node that does not use the Keyryx signer is unaffected.
- **A signature is checked before it is kept.** Each signature Keyryx returns is verified against the root statement the seal made for that root, tenant, shard count and queued time. One that does not verify is not stored, and its root stays queued, so a pack built while it is queued says the root is unsigned. Before this release a returned signature was stored as it came.
- **A key set in rotation is read for the pinned key only.** Keyryx may publish the pinned key beside its successor while it rotates. The node takes the key whose thumbprint is the pin and passes over the others. A key set without the pinned key is refused, and the signer then holds no key and signs nothing under that set.
- **`TRAILRYX_KEYRYX_KID` is a new variable.** It is listed in `COMPATIBILITY.md` and `compat/1.0.json` beside the other Keyryx signer variables.

## What changed since 1.4.0

- **The Keyryx signer takes one pinned key (#112).** The seal signs under the key `TRAILRYX_KEYRYX_KID` names, and the node reads Keyryx's key set for that key only.
- **Each Keyryx signature is verified before it is stored.** The check is the P-384 verifier in `trailryx-verify`, applied to the root statement described under Upgrading.
- **Invariant 52 and `features/keyryx-signing.feature` state the rule.** The feature file has eight scenarios, each bound to a test in `trailryx-node`.
- **Test counts.** The README states 1332 tests across 31 crates, up from 1323.

## Why a minor

The frozen section of `COMPATIBILITY.md` is unchanged. The only compat change adds `TRAILRYX_KEYRYX_KID` to the additive entry for the Keyryx signer, which is optional and unset by default. The start refusal stops one deployment shape, a node that chose the Keyryx signer and named no key. That deployment adds one variable to start again.

## Not proven

- **Against a live Keyryx.** The signer is tested against a stub Keyryx on a loopback port inside `trailryx-node`'s integration tests. Nothing in this release was run against a running Keyryx.
- **The Rust suite on this commit.** The change was prepared on a machine that does not run the Rust suite. CI on the release commit is the first full run of it.
