# Trailryx 1.2.0

A minor release on the 1.0 surface: the record plane seals two new agent-event
types from TokenFuse, which mean money held for a person and money released by
one. Nothing is removed or renamed, and no record, journal or pack format
changes.

## What changed since 1.1.0

- **`call_retained` and `retained_closed` are mapped (#94, D10).** TokenFuse
  1.10.0 writes two events that agent-passport SPEC 6.2 now registers under
  `tokenfuse`. `call_retained` (medium) is a call whose outcome became unknown,
  so its money stays reserved until a person closes it; it maps to a
  `BudgetCheck` with the verdict `Held` and the band `Warning`. `retained_closed`
  (high) is a person closing that reservation with evidence; it maps to a
  `BudgetCheck` with the verdict `NotApplicable` and the band `Error`, read the
  way `taint_cleared` is: a hold lifted on a person's word. Neither carries an
  error code, because nobody knows whether the caller left or the connection
  broke. The typed metadata is the same eight members as before; everything in
  `data`, including the evidence reference a person typed, stays in the payload
  plane and is never promoted. `MAPPER_VERSION` moves from 111 to 112, because
  stored records gain a new mapping. This is the reason the release is a minor:
  a new event type that the mapper newly accepts is additive in
  `compat/1.0.json`.
- **The workspace version and the README's image lines** name 1.2.0 (the 31
  workspace crates in the lock), so `readme-numbers.sh` holds.
- **Advisory and toolchain (#90, #91).** `time` moves to 0.3.47 for
  GHSA-r6v5-fh4h-64xc, and its audit ignore is dropped. The workspace declares
  Rust 1.88 and `trailryx-sql` declares 1.89.
- **Documentation (#87, #89).** The README describes the ingest listener's
  `/healthz` and the federation gRPC transport. The mapper's module documentation
  refuses costcrew's `anomaly_hinted` by name, as it does the other refused types.
- **Build and CI (#88, #92).** One integration-test binary per crate, and less
  development debug info. The estate secret scan runs on every pull request and
  push to `main`.

## Upgrading

- **From 1.1.0, nothing to configure.** No flag, environment variable or format
  changes.
- **The trail of money held for a person starts at 112.** A line of either new
  type that a 1.1.0 reader met was refused as an unknown type, and its cursor
  moved past it, so 1.2.0 does not go back for those lines. A line refused by
  1.1.0 stays unrecorded; this release does not repair that.
- **The stack launchers pin `trailryx-node:v1.0.0`**, which predates this
  mapping. A launcher that wants these records must bump its pin; until then the
  record refuses the two types, as 1.0.0 did.

## Not proven

- **A real TokenFuse bus.** The mapping was tested with constructed envelopes.
  No line written by a running TokenFuse 1.10.0 was run through `trailryx-node`.
- **Coverage.** CI has no coverage step, so none was measured.
- **The record over a stack.** `trailryx-node events` was not run over a bus
  that carries either type.
