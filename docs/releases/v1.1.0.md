# Trailryx 1.1.0

A minor release on the 1.0 surface: one new route on the ingest listener, a
TLS security update, and documentation of what the record plane refuses by
name. Nothing is removed or renamed, and no record, journal or pack format
changes.

## What changed since 1.0.0

- **`GET /healthz` on the ingest listener (#76).** A readiness path for
  launchers and orchestrators. It answers 200 while the ingest source is
  healthy and 503 with the body "the ingest path is degraded" once the source
  is degraded or its lock is poisoned. It is decided before the pending-queue
  and in-flight body budgets, so a plane that is busy reads as busy and not as
  broken. It is subject to the connection cap, answers with `Connection: close`,
  and needs no credential. Any other method on it answers 405. It is listed
  under "Additive within a major" in `COMPATIBILITY.md` and `compat/1.0.json`,
  and as `health_path` in `components.json`. This is the reason the release is
  a minor and not a patch.
- **rustls 0.23.45 (#75).** See the security note below.
- **Refused by name, documentation only (#77, #81, #84).** The agent-event
  mapper's module documentation now names the types the record plane refuses
  and why: `run_stalled`, typryx's `typed_answer`, `typed_unanswered`,
  `typed_refused` and `calibration_drift`, and agent-conform's `chain_broken`
  and `chain_unchained`. No mapping arm changed, `MAPPER_VERSION` stays at 111,
  and a refusal produces no record, so no stored record reads differently.
- **Build on rustc 1.99 (#85).** CI floats on stable, which deprecated
  `AtomicUsize::fetch_update`; its replacement does not exist at the 1.85 MSRV,
  so the call stays and the lint is allowed on that one function. No behaviour
  change. `async-trait` moves to 0.1.92 in the lockfile.
- **Validation records (#78, #83).** Two runs of the 1.0.0 record plane
  written into `VALIDATION.md`: the `record-seal` service on a box behind a
  home router (2026-09-17), and a `record-seal` Job after a governed Hermes
  team on a three-node k3d cluster (2026-09-27).
- **GitHub Actions pins (#79, #82).** Dependabot moves
  `docker/build-push-action` to v7.4.0 in `release.yml` and
  `github/codeql-action/upload-sarif` in `scorecard.yml`, each still pinned to
  a commit.

## Security

RUSTSEC-2026-0285: rustls 0.23.43 accepted TLS 1.3 handshake messages across
encryption level boundaries; fixed in 0.23.45. rustls reaches three of this
workspace's crates on normal dependency edges (`trailryx-federation-grpc`,
`trailryx-http` behind its `tls` feature, and `trailryx-sql`), so the advisory
was not silenced; the lockfile moved. Companion moves forced by the resolver:
rustls-webpki 0.103.13 to 0.103.15, aws-lc-rs 1.17.3 to 1.18.1, aws-lc-sys
0.43.0 to 0.45.0, aws-lc-fips-sys 0.13.16 to 0.14.2. For anyone who builds with
the `fips` feature: the bundled AWS-LC library behind it moves from 3.4.0 to
4.2.0 (the `AWSLC_VERSION_NUMBER_STRING` in the two crates' vendored sources),
so check which module version any approval you rely on names. The default
image and binaries do not use that feature.

## Upgrade note, 1.0.0 to 1.1.0

- The only new surface is `GET /healthz` on `trailryx-ingest` (and on the
  ingest listener inside `trailryx-node run`). A probe that used to get 404
  there now gets 200 or 503. Nothing else answers differently.
- Nothing is removed or renamed. The frozen surface in `COMPATIBILITY.md` is
  unchanged: the same ten binaries, two routine names, three subcommands,
  fifteen environment names, `/v1/traces`, three agent-event schema versions,
  eight consumed envelope fields and the journal's frame magic and format
  version.
- Records, packs and cursors need no migration. A store sealed by 1.0.0 reads
  under 1.1.0 and the other way round; the record and journal formats did not
  change in this range.
- Pull lines in the README now name `v1.1.0` for both images.

## Not proven

- This release has not been through a proving run of its own. The two
  validation records above ran 1.0.0 images, and the 1.0 proving run measured
  1.0.0.
- `GET /healthz` is held by wire tests in the crate. It has not been probed by
  an orchestrator: nothing in the stack's launchers polls trailryx yet. In
  `trailryx-node run` a poisoned source makes the process exit on its next
  poll instead of serving the 503.
- The `fips` build against rustls 0.23.45 and AWS-LC 4.2.0 is proven by CI's
  gate only, not by a run on a validated deployment. The federation transport
  was not exercised against a live peer after the rustls move; only its tests
  ran. Three allowed `cargo audit` warnings (paste and rustls-pemfile
  unmaintained, chacha20 yanked) are unchanged.
- The rustc 1.99 fix was red only in CI (the local toolchain, 1.96.1, does not
  raise the lint), so it has no local red-first run.
- Still unmeasured, as `VALIDATION.md` says: receiver throughput of `/v1/traces`
  under load, the plane under sustained concurrent load, a machine dying
  rather than a process (power loss against a real block layer), the
  federation transport across an actual network, and an external audit of the
  cryptographic layer.
- Packs still carry no root signature and no witness unless an operator wires
  one in; `trailryx-verify` says so in its own `[weak]` lines, and `VERIFIED`
  means self-consistency, not authorship.
- The record plane accepts one trust domain per run; events minted under any
  other domain are refused as foreign, by design.
