# Trailryx 1.6.0

A minor release on the 1.x surface. The agent-event reader maps the two ways a wardryx hold now closes without a person's decision, so a hold that expired or was withdrawn gets its closing record, and the lockfile moves past every advisory with a reachable fix. The frozen section of `COMPATIBILITY.md` is unchanged, and no record, journal, pack or wire format changes.

## Upgrading

- **Nothing to configure.** Replace the 1.5.0 images (`trailryx`, `trailryx-node`) with 1.6.0. No variable, flag or file changes.
- **Two event types now map (`MAPPER_VERSION` 115).** wardryx 2.8.0 closes a hold as `approval_expired` after its lifetime and as `approval_withdrawn` when its own agent withdraws it, both registered under wardryx in agent-passport SPEC 6.2. Under 1.5.0 each was refused as an unknown type and counted. Under 1.6.0:

  | type | event type | verdict | error | band when the line carries no severity |
  |---|---|---|---|---|
  | `approval_expired` | PolicyDecision | Failed | Timeout | Warning |
  | `approval_withdrawn` | PolicyDecision | NotApplicable | none | Info |

  Neither reads as `Denied`. A cursor that already moved past such lines under 1.5.0 does not go back for them: the closing records start with the first line read under 1.6.0, and a record carries the mapper version that wrote it.

## What changed since 1.5.0

- **#124: `approval_expired` and `approval_withdrawn` are mapped.** Test `a_hold_closed_by_its_lifetime_or_its_agent_is_not_a_denial`, bound by `features/a-hold-that-closes-without-a-person.feature`.
- **#115 and #121: the lockfile clears every advisory with a reachable fix.** ctutils 0.4.6, rustls-webpki 0.103.16, webpki-roots 1.0.11, pulldown-cmark 0.13.6, zstd-sys 2.1.2, and parquet and the arrow crates 58.4.1, which bring thrift 0.23. zstd 0.13.3 and zstd-safe 7.2.1 stay, accepted as a bounded risk until a DataFusion release takes parquet and arrow-ipc 60 (invariant 24); `scripts/audit.sh` fails the build when that exit condition is reached.
- **#122: no gate ends a pipe in a reader that leaves early** (invariant 53, `scripts/no-reader-leaves-a-pipe-early.sh`).
- **#117: CI counts the README's test numbers from the suite run it already did**, instead of running the suite again per crate.
- **#120:** the README says stack-single seals the record too. **#116, #123:** CI actions move to newer pinned commits.
- **Test counts.** The README states 1333 tests across 31 crates, up from 1332.

## Why a minor

A newly accepted agent-event type is listed as additive in `compat/1.0.json`. The frozen section is unchanged.
