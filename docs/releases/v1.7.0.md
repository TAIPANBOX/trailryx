# Trailryx 1.7.0

A minor release on the 1.x surface. The OTLP mapper files a span that names no agent under the agent its trace names, so one run of one agent is recorded under one agent id, and the agent-event reader maps two more event types it used to refuse. The lockfile moves past one advisory with a reachable fix. The frozen section of `COMPATIBILITY.md` is unchanged, and no record, journal, pack or wire format changes.

## Upgrading

- **Nothing to configure.** Replace the 1.6.0 images (`trailryx`, `trailryx-node`) with 1.7.0. No variable, flag or file changes.
- **The OTLP mapper is at `MAPPER_VERSION` 3.** A span with no `gen_ai.agent.name` now takes the agent named by the other spans of its trace, within the same `service.name` and, at the agent-token door, the same caller. Before, it fell back to `service.name`, so one run could be filed under two agent ids. A trace that names two agents lends neither, so those spans keep their previous fallback. Each record carries the mapper version that wrote it.
- **The agent-event reader is at `MAPPER_VERSION` 116.** Two more event types now map instead of being refused:

  | type | event type | verdict | error | severity |
  |---|---|---|---|---|
  | `rate_limited` | PolicyDecision | Denied | RateLimited | Medium |
  | `price_fallback` | BudgetCheck | none | none | Low |

  `rate_limited` is the breaker-tripped reading. `price_fallback` is read with `budget_threshold` and `spend_spike`.

## What changed since 1.6.0

- **#80: one run of one agent is filed under one agent id.** New invariant 54 (`MAPPER_VERSION` 3 for the OTLP reader). Scenarios in `features/otlp-one-run-one-agent.feature`.
- **`rate_limited` and `price_fallback` are mapped** (`MAPPER_VERSION` 116). A newly accepted type is additive, and the frozen section is unchanged.
- **#127: a weekly `cargo audit` run.** The `vulnscan` workflow runs `scripts/audit.sh` once a week, the same script CI runs on each push.
- **Dependency: `url` 2.5.9 and `form_urlencoded` 1.2.3** clear RUSTSEC-2026-0592, a stack overflow in `Url::origin` on nested `blob:` URLs. Nothing else in `Cargo.lock` changes.

## Why a minor

Two event types are newly accepted and the OTLP mapper resolves agents differently for spans that name none. Both are additive on the frozen surface, and nothing already written is redefined.
