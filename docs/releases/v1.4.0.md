# Trailryx 1.4.0

A minor release on the 1.x surface. The agent-event reader accepts the v1.0 schema
that agent-passport SPEC 6.4.1 asks a consumer to accept, and it refuses a claimed
subject under every accepted version. Nothing in the frozen surface in
`COMPATIBILITY.md` is removed or renamed, and no record, journal, pack or wire
format changes.

## Upgrading

Read this section before deploying.

- **Lines stamped v1.0 are now read.** Before this release they were counted as
  `unknown_schema` before their subject or type was looked at. Now a v1.0 line is
  read exactly as the same line stamped v0.3 is. Expect the `unknown_schema`
  counter to fall for those lines.
- **Agent-conform and keyryx lines are refused by type, and the counters say so.**
  Their types (`chain_broken`, `chain_unchained`, `key_rotated`, `key_revoked` and
  the seven `witness_*` types) are refused as `unknown_type`, and a claimed subject
  is refused as `claimed_subject`. None of them becomes a record. They were not
  records before this release either: the refusal moved from the schema check to
  the type check, and the outcome did not change.
- **The mapper reading moves from 113 to 114.** Records written from this release
  carry mapper reading 114, and the trail of v1.0 events starts there. Lines
  stamped v1.0 that an earlier import already read and passed over are not read
  again: the import cursor moved past them. This release adds no command to reset
  that cursor, so those lines stay unrecorded unless their file is re-imported
  some other way.
- **wardryx decisions without a run.** A wardryx decision line becomes a policy
  decision record when its request named a run. A line with no `run_id`, such as
  the checkpoint test vectors in agent-passport, is counted as `no_run_id`. This
  release does not supply a run.
- **Nothing to configure.** No flag, environment variable, route, schema of a
  stored record or pack format moves, and existing records are not rewritten.

## What changed since 1.3.1

- **agent-event v1.0 is accepted (#110).** `taipanbox.dev/agent-event/v1.0` joins
  the accepted schemas. The refusal of a claimed subject moves from the version to
  the subject, so a `claimed:` agent is refused by name under v0.1, v0.2, v0.3 and
  v1.0, and the prefix is never stripped. A version the reader does not name,
  v1.1 included, is still refused by its schema.
- **The ten types the module names are refused by type.** Under v1.0 the agent-conform
  and keyryx types it names are refused by type and never written as an agent's
  decision. `key_rotated` and `key_revoked` are not named there, so they are refused
  as unmapped types.
- **Test counts.** The README states 1323 tests across 31 crates, and the
  `trailryx-agentevent` crate runs 66.

## Why a minor

The reader gains a schema it did not accept, and lines that were counted as unknown
are now read and classified. That is an addition. The frozen section of
`COMPATIBILITY.md` is unchanged, and v1.0 falls under the existing additive entry
for the agent-event schema version this reader accepts.

## Not proven

- **The v1.0 shape.** The reading of agent-passport SPEC 6.4.1 used here was made
  outside this repository. The fixtures are the wardryx checkpoint vectors and the
  agent-conform and keyryx lines as they were supplied, not output captured from
  those producers in this build.
- **Producers running this release.** No agent-conform or keyryx producer has yet
  been run end to end against this reader.
- **Image signing.** The signing step is the one shipped in 1.3.1, unchanged. As in
  1.3.1, it is first exercised by this tag.
