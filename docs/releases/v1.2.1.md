# Trailryx 1.2.1

A patch release on the 1.2 surface: a TLS security update in rustls, a CI
action bump in the release workflow, and documentation. Nothing is added, removed
or renamed, and no record, journal, pack or wire format changes.

## What changed since 1.2.0

- **rustls 0.23.46 (#99).** Four advisories are fixed in rustls 0.23.46 and not
  in 0.23.45, and the audit gate was red on `main` until this lockfile moved:
  RUSTSEC-2026-0346 (the Debug output of client session values could show TLS
  secrets), RUSTSEC-2026-0347 (application data buffered for an outer server
  after an Encrypted Client Hello was rejected could be sent to that server),
  RUSTSEC-2026-0348 (Brotli certificate decompression could allocate up to 1 GiB
  before authentication) and RUSTSEC-2026-0349 (an unauthenticated ServerHello
  could downgrade later connections to classical key exchange). The lockfile
  moves rustls and its checksum and nothing else; `Cargo.toml` is unchanged.
  rustls reaches `trailryx-sql` and `trailryx-federation-grpc` on normal
  dependency edges, and `trailryx-http` through its `tls` feature.
- **Release workflow action pins (#93).** Dependabot moves
  `actions/upload-artifact` to v7.0.2, `actions/download-artifact` to v8.0.2 and
  `anchore/sbom-action` to v0.24.3 in `release.yml`, and
  `github/codeql-action/upload-sarif` to v4.38.3 in `scorecard.yml`. Each is
  still pinned to a commit.
- **Documentation (#96, #97, #98).** The node image's Dockerfile comment names
  the `run` subcommand (#96). The README states the cold build time with its
  date and machine, and `VALIDATION.md` carries the measurement behind it (#97).
  The planning documents under `docs/planning` are in English, with the
  quotations in them paraphrased, and the messages `scripts/kill-linux.sh`
  prints are in English too (#98).

## Why a patch

Nothing new is observable: no route, event type, flag, schema or format has
changed since 1.2.0. The rustls change is a security fix to a dependency, which
is a patch under the SemVer reading in `COMPATIBILITY.md`, where only an additive
thing moves the minor.

## Upgrading

- **From 1.2.0, nothing to configure.** No flag, environment variable, route or
  format changes. The frozen surface in `COMPATIBILITY.md` is unchanged.
- **The TLS stack is the fixed rustls.** A deployment that uses the `tls` feature
  of `trailryx-http`, or the gRPC federation transport, gets the fix by moving to
  this release.

## Not proven

- **A live TLS peer.** The rustls change is checked by the audit gate and by CI's
  build and tests. No TLS handshake was run against a real peer for this release.
- **The release workflow with the new action pins.** `release.yml` runs only on a
  `v*` tag, so this tag is the first run of the bumped actions.
- **Coverage.** CI has no coverage step, so none was measured.
