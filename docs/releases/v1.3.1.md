# Trailryx 1.3.1

A patch release on the 1.3 surface: the two container images are signed in
cosign's legacy `.sig` format, so an admission controller that reads only that
format can verify them. No code changes. Nothing is added, removed or renamed,
and no record, journal, pack or wire format changes.

## What changed since 1.3.0

- **Image signatures in the legacy `.sig` format (#108).** The release workflow
  signs `ghcr.io/taipanbox/trailryx` and `ghcr.io/taipanbox/trailryx-node` with
  `cosign sign --yes --new-bundle-format=false --use-signing-config=false`. By
  default cosign v3 writes the newer Sigstore bundle format, and Sigstore
  policy-controller v0.15.1 reads only the legacy `.sig` tag. cosign stays at
  v3.1.3, each image is still signed keyless and by digest, and the provenance
  attestations and the `sign-blob` bundle over `SHA256SUMS` are unchanged. Both
  flags come out once policy-controller reads bundles (sigstore/policy-controller
  PR #1968).
- **Version.** The workspace version, the lockfile's entries for the workspace
  crates and the three image lines in the README move to 1.3.1.

Nothing else is on `main` since the 1.3.0 tag.

## Why a patch

Nothing a deployment runs is different: the crates' code is the code 1.3.0
shipped, and no route, event type, flag, environment variable, schema or format
has changed. The change is in how the release workflow signs the images, which
adds nothing to the surface `COMPATIBILITY.md` describes, so it moves neither the
major nor the minor.

## Upgrading

- **From 1.3.0, nothing to configure.** The frozen surface in `COMPATIBILITY.md`
  is unchanged.
- **A cluster that admits images through policy-controller v0.15.1** should pin
  `trailryx:v1.3.1` and `trailryx-node:v1.3.1`. The 1.3.0 images keep the
  bundle-format signatures they were published with; this release does not
  re-sign them.
- **The stack launchers** get the legacy-format signatures by moving their pins to
  `trailryx:v1.3.1` and `trailryx-node:v1.3.1`. This release changes no launcher.

## Not proven

- **The signing step with the two flags.** `release.yml` runs only on a `v*` tag,
  so this tag is the first run of `cosign sign` with them. No signature this
  workflow wrote in the legacy format had been read back before the tag.
- **Admission by policy-controller.** No cluster running policy-controller
  v0.15.1 had admitted a trailryx image signed this way before the tag.
- **Coverage.** CI has no coverage step, so none was measured.
