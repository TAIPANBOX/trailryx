# Trailryx 1.0.0

The record plane of the TAIPANBOX stack: an append-only, sealed, verifiable
journal of what agents did, fed from the shared agent-event bus, with a
verifier anyone can run on a pack without trusting the node that sealed it.

## What 1.0 promises

`compat/1.0.json`, rendered as `COMPATIBILITY.md` and held by
`scripts/compat-surface.sh` on every push: the ten binaries, the two routine
names, the three `trailryx-node` subcommands, the fifteen environment names,
the `/v1/traces` route, the three agent-event schema versions this reader
accepts, the eight envelope fields it consumes, and the journal's frame magic
and format version. A frozen name is not removed or renamed within this major.
Support line: the newest minor gets every fix; the previous minor gets
security-relevant fixes for 90 days after the newer one is tagged.

## Proven, by the 1.0 proving run (estate-gates `PROVEN.md`, section "The 1.0 proving run")

- **REC-2, R2.** A pack sealed by the record-seal routine on a five-node GCP
  cluster, copied out, verified by `trailryx-verify` from the published image
  on another machine with no network: **VERIFIED**; one byte flipped, at two
  different offsets: **NOT VERIFIED**, with the broken chain, history root and
  index roots named line by line.
- **REC-1, R2 on GCP and AWS.** The seal routine over the live bus: every
  event under the cluster's trust domain mapped and sealed; every event outside
  it refused as foreign with the cursor held (trailryx#50's behaviour), and the
  sealed segments answered with a full completeness proof.
- **R3.** The seal over six gateways' event files and one pack of 15 records
  across 5 segments, VERIFIED.
- **UPG-3, R1.** Records sealed by the `trailryx-node:v0.1.2` image verified by a
  `trailryx-verify` built from main: the pack format is read across versions.
- **REC-3, R1.** `trailryx-demo --runs 2`: keys destroyed over payloads, the
  same pack VERIFIED again byte for byte, payloads unreachable afterwards.
- **FAIL-5, R1.** The journal on a full disk: `No space left on device`, exit 2,
  no cursor written, the store reads back exactly what it held before.
- **INS-7, R1.** The README's install block and first commands run literally on
  a clean box.

## Upgrade note, 0.1.x to 1.0.0

Records are the chain and are never rewritten: a store sealed by 0.1.x reads
under 1.0.0 (UPG-3 above measured exactly that direction), and a pack written by
either verifies with either verifier. Cursors (`*.cur`) carry on where they
were. The three accepted agent-event schema versions are unchanged. Nothing
needs migrating; a node restarted on the new binary continues the same shard.

## Not in this release, said plainly

- Receiver throughput of `/v1/traces` under load stays unmeasured, as
  `VALIDATION.md` says.
- Packs carry no root signature and no witness yet; `trailryx-verify` says so
  in its own `[weak]` lines, and it means self-consistency, not authorship.
- The record plane accepts one trust domain per run; the drills'
  `agent://mockryx.local/*` identities are refused by design on every stack
  deployment (a decision recorded in the R2 evidence, not a defect here).
